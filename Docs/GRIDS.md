# Гриды

Система гридов хранит тайлы в клетках с целочисленными координатами, получает их определения из общего реестра и строит меши чанков для отображения и коллизий. Основные компоненты находятся в `Assets/Episeanter/Scripts/Grid`, определения тайлов — в `Assets/Episeanter/Scripts/Tiles`.

## Компоненты

- `Grid` хранит логические данные тайлов. Непустые ID тайлов хранятся в чанках; при изменении клетки вызывается событие `TileChanged`.
- `GridVisual` хранит визуальные данные тайлов, создаёт для чанков объекты `MeshFilter`, `MeshRenderer` и `MeshCollider`, а также перестраивает помеченные как изменённые меши в `LateUpdate`. Кроме того, он применяет текстурный атлас dual-grid к видимым граням.
- `Damageable` хранит здоровье клеток, принимает урон и настраивает общий материал слоя повреждений и число его стадий.
- `NetworkGrid` связывает грид с Mirror. Сервер владеет логическим состоянием; клиенты получают начальный снимок и последующие визуальные обновления, включая здоровье. Настройка сети описана в [NETWORKING.md](./NETWORKING.md).
- `TileDefinition` задаёт материалы тайла, максимальное здоровье и порог минимального урона. `TileRegistry` связывает стабильные ненулевые ID с определениями.

На GameObject грида должны находиться компоненты `Grid` и `GridVisual`. Добавьте `Damageable`, чтобы включить здоровье и слой повреждений; сетевой грид также требует `NetworkIdentity` и `NetworkGrid`. Пример такой настройки — префаб `Grid`.

## Координаты и хранение

Клетки задаются через `Vector3Int(x, y, z)` в локальном пространстве грида. Размер каждой клетки — одна единица; `y` задаёт высоту и должен находиться в диапазоне от `0` до `HeightLimit - 1`. Грид может расширяться в обоих направлениях по локальным осям `x` и `z`.

`CellToWorld(position)` преобразует локальные координаты клетки и возвращает её начало в мировом пространстве. Чтобы получить центр клетки, прибавьте к этой точке `(0.5, 0.5, 0.5)`.

`ChunkSize` задаёт количество клеток вдоль каждой горизонтальной оси чанка. Чанки — внутренняя деталь хранения и построения мешей: вызывающий код по-прежнему использует координаты клеток относительно всего грида. Поддерживаются отрицательные координаты.

## Реестр тайлов и материалы

Добавьте `TileRegistry` в загруженную сцену и заполните его записями с уникальными ID и ресурсами `TileDefinition`. Реестр сохраняется между сменами сцен. ID `0` зарезервирован для пустой клетки. Сохраняйте соответствие ID определениям неизменным в сохранениях и у всех участников мультиплеера: при смене соответствия существующий ID будет обозначать другой тайл.

Для каждого определения тайла необходим материал. Если у материала есть текстура, её ширина и высота должны делиться на четыре: текстура используется как атлас dual-grid размером 4×4. Для верхней грани используется `Material`; для боковых — `SideMaterial`, который при отсутствии заданного материала использует `Material`. Нижняя грань не создаётся. Ячейки атласа выбираются по соседним клеткам с тем же ID тайла.

`MaxHealth` задаёт начальное здоровье тайла, а `MinimumDamage` отбрасывает атаки, чей урон меньше порога. В `Damageable` укажите общий `DamageLayerMaterial` и `DamageStages`. Текстура этого материала должна содержать стадии повреждения горизонтальной полосой; число пикселей по ширине должно быть не меньше числа стадий, но делиться на него без остатка не обязательно. Для чёткого отображения небольшого пиксельного атласа отключите mipmaps и компрессию в настройках импорта. Все клетки и грани используют один материал. Чем меньше осталось здоровья, тем дальше вправо выбирается стадия; при уничтожении тайл удаляется.

Урон наносится вызовом `damageable.DamageTile(cell, amount)`, текущее здоровье читается через `damageable.GetHealth(cell)`. При наличии `NetworkGrid` запрос урона проверяется и применяется сервером; в локальном гриде применяется сразу.

## Работа с `Grid`

Для чтения и изменения клеток используйте логический API грида:

```csharp
Vector3Int cell = new Vector3Int(1, 0, 1);

grid.SetTile(cell, tileId);                 // Или передайте зарегистрированный TileDefinition.
uint id = grid.GetTileId(cell);             // 0 означает пустую клетку.
bool exists = grid.TryGetTileId(cell, out id);
bool removed = grid.RemoveTile(cell);
Vector3 worldOrigin = grid.CellToWorld(cell);
```

`SetTile` принимает зарегистрированный ID тайла или его определение и не допускает ID `0`. При высоте за пределами заданного диапазона метод выбрасывает исключение. `RemoveTile` также проверяет высоту и возвращает `false`, если клетка уже пуста. `TryGetTileId` возвращает `false` для пустой клетки и высоты за пределами диапазона; `GetTileId` возвращает `0` для пустой клетки и выбрасывает исключение при недопустимой высоте.

Если ID клетки действительно изменился, вызывается событие `Grid.TileChanged` с новым ID. При удалении тайла событие получает ID `0`. Повторная запись того же ID событие не вызывает.

## Визуализация и взаимодействие

В локальном, не сетевом гриде `GridVisual` отслеживает событие `Grid.TileChanged` и отображает логическое состояние. Методы `GetVisualTileId`, `TryGetVisualTileId`, `GetTile` и `TryGetTile` позволяют читать локальное визуальное состояние. `ApplyVisualTile` и `RemoveVisualTile` предназначены для применения визуальных изменений; ID визуального тайла `0` зарезервирован для пустой клетки.

`GridClickInteraction` — необязательный пример компонента ввода. Он выполняет raycast по коллайдерам, наносит настроенное количество урона левой кнопкой мыши и размещает тайл с настроенным ID правой кнопкой. У цели должны быть компоненты `Damageable` и коллайдер, созданный `GridVisual`; маска слоёв и дальность raycast должны включать этот объект. В сетевой сессии компонент отправляет запрос урона серверу, а не изменяет логический грид напрямую.

## Поведение в мультиплеере

Авторитетным является `Grid` на сервере. Удалённый клиент помечается как реплика, и его логические данные очищаются; прямые изменения такой реплики запрещены. После спавна сетевого грида клиент запрашивает текущее состояние сервера. Сервер отправляет его пакетами до 512 клеток, а затем рассылает последующие изменения.

Запросы клиента на изменение проверяются на сервере. `NetworkGrid` проверяет высоту клетки, настройку `allowClientEdits`, наличие у отправителя объекта игрока, расстояние от игрока до центра клетки (`maxEditDistance`) и ID устанавливаемого тайла. Эти проверки не заменяют игровые правила строительства: прежде чем разрешать свободное строительство, добавьте необходимые правила в серверную проверку изменений.
